The quantisation weight matrices in ProResProfile.cs are the profile tables carried
by FFmpeg (https://ffmpeg.org) in its LGPL ProRes encoders. The original four 4:2:2
pairs match libavcodec/proresenc_kostya.c's prores_quant_matrices. The 4444 profile
uses the HQ matrix for luma and chroma, and 4444 XQ uses FFmpeg's XQ luma table with
the HQ chroma table; those choices are also present in libavcodec/proresenc_anatoliy.c
as QMAT_LUMA/QMAT_CHROMA.

SMPTE RDD 36 prints none of these profile matrices: it describes the bitstream and
decoding process, and a decoder is told the matrices by every frame it reads. The
matrix values are therefore interoperability constants rather than an implementation
of FFmpeg's encoder. They have additionally been checked against frame headers written
by FFmpeg where an encoder exposes the corresponding profile.

Nothing else in this directory is copied or translated from FFmpeg. The bitstream
syntax, entropy codes, block scans, transforms, alpha coding and field-picture handling
are implemented from SMPTE RDD 36:2022 and are cited by clause in the source. FFmpeg is
used as a behavioural oracle.

Relevant FFmpeg sources:

  libavcodec/proresenc_kostya.c    prores_quant_matrices for the 4:2:2 profiles
  libavcodec/proresenc_anatoliy.c  QMAT_LUMA/QMAT_CHROMA, including 4444/XQ tables
